# Data folder layout

```
veritas/data/                   ← gitignored — never commit evidence or DB contents
├── postgres/                   # Postgres database files (auth, audit log, cases)
│                               # Created automatically on first `docker compose up`
│
├── redis/                      # Redis append-only log (Celery queue persistence)
│                               # Created automatically on first `docker compose up`
│
├── neo4j/                      # Neo4j graph database + logs + import directory
│   ├── data/                   # -- graph nodes, relationships
│   ├── logs/                   # -- Neo4j runtime logs
│   └── import/                 # -- for bulk CSV import operations
│                               # Created automatically on first `docker compose up`
│
├── evidence_storage/           # Raw evidence files mounted into containers
│                               # Place files here or configure a different path in .env
│
└── backups/                    # Neo4j dump files (generated by backup script)
    └── neo4j_backup_*.dump     # Timestamped, created by backend/scripts/backup_neo4j.sh
```

## Why not in git?

- **Security** — evidence files, DB contents, and backup dumps contain case-sensitive data
- **Size** — databases and model weights can be gigabytes, making clone/push impractical
- **Portability** — each deployment (cyber cell) has its own data; the repo only ships the code

## How it gets created

Docker Compose uses **bind-mounts** — the paths in `docker-compose.yml` map container
directories to these host folders. If a folder doesn't exist on first run, Docker
creates it automatically. No manual setup needed.
